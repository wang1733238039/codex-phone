# 托管版账号与运营

0.6.0 在一个服务、一份 SQLite 数据库中管理多个账号。免费自托管与托管版使用同一代码，安装方式不变。新账号默认没有电脑，也没有其他人的缓存。

## 首个管理员与旧版本升级

- 新安装继续执行 `npm run setup`，首次启动时将配置账号导入数据库，设为管理员、长期有效、最多 50 台电脑。
- 从 0.5.0 升级时，原账号、密码、主电脑 ID、已配对电脑、历史、附件和未到期登录均保留，原账号自动成为管理员。
- 首次升级已有设备的数据库时，会在数据库旁生成 `cache.sqlite.before-accounts-时间戳.sqlite` 一致性备份；其中含凭据摘要与缓存，须留在私有数据目录。
- 迁移后登录密码以数据库为准，修改 `server.json` 中的 `passwordHash` 不会覆盖账号密码。使用账户页修改管理员密码；普通用户忘记密码时由管理员重置。
- 不要更改现有 `ownerId` 或把其他环境的数据目录覆盖到本实例。
- 服务器 0.6.0 兼容现有 0.5.0 连接程序，升级服务器不要求其他电脑重新配对。

先按部署文档备份整个数据目录，再更新源码和容器。迁移自动备份仅包含 SQLite，不替代附件、配置及版本的完整备份。回滚使用匹配的旧版本、配置和数据库，不能把 0.5.0 直接指向升级后的数据库。

## 开通第一位客户

1. 管理员登录网站，在 **账户与套餐 → 管理用户与邀请** 打开管理页。手机会话顶部也可进入账户页。
2. 选择“生成邀请”，设置服务天数、电脑上限和邀请有效天数。默认分别为 30、3、7。
3. 复制邀请链接，交给指定客户。链接是短期的一次性凭据，只显示一次，不能公开广播。失去链接可撤销后重新生成。
4. 客户打开链接，设置自己的账号和至少 10 个字符的密码。注册时开始计算服务期；邀请创建后未兑换不会消耗套餐天数。
5. 客户登录自己的账号，点击电脑菜单的“添加电脑”，用 5 分钟内有效的一次性配对码绑定自己的连接程序。
6. 客户手机登录同一账号，即可切换自己绑定的电脑、查看历史和继续任务。

可以改选“直接创建账号”，由管理员设置初始密码、服务天数和电脑上限。新账号用户名为 3–80 位字母、数字或 `_.@-`，不区分大小写；管理员应通过用户认可的私密渠道交付密码，建议用户首次登录后修改。

目前采用人工确认收款和人工开通/续期。若按 9.9 元每月运营，可以每次确认收款后增加 30 天。此处的“月”按 30 天服务期执行，界面会显示准确到期时间。系统不包含支付订单、支付回调、自动扣费、短信或邮件找回功能，也不会自动向客户发送消息。

## 续期、停用与删除

| 操作 | 行为 |
| --- | --- |
| 续期 | 未到期从原到期时间顺延；已到期从当前时间起算。续期本身不会恢复人工停用的账号，需要另点“恢复账号”。 |
| 修改期限 | 管理页按浏览器本地时区输入准确时间，服务端保存 UTC 时间戳。已打开的页面会刷新账号状态。 |
| 自然到期 | 到期检查断开电脑中继连接并撤销未兑换配对码；仍可登录、查看自己已经缓存的内容、修改密码、解绑和删除账号。禁止配对、上传、新建、发送、模型读取、审批和停止操作。 |
| 续期后恢复 | 连接程序使用原设备令牌重连，无需重新配对。 |
| 停用 | 立即撤销登录、断开事件流与电脑连接并撤销配对码。保留数据与设备令牌，恢复后用户可重新登录，连接程序可重连。 |
| 重置密码 | 撤销此账号全部网页登录，其他账号不受影响。不会替用户重置电脑本地 Codex 密钥。 |
| 降低电脑上限 | 不强制解绑现有电脑；已有设备数达到或超过上限时，不能新增电脑。 |
| 解绑电脑 | 原设备令牌立即失效。不能用请求中的 ownerId 转让电脑；需要以目标账号重新配对。 |
| 删除账号 | 撤销凭据与连接，删除云端设备记录、会话缓存、命令回执、配对码及附件。保留无密码的删除标记与最少审计元数据，已用用户名不再重复分配。 |

管理员入口只管理普通用户，不能停用、删除或重置管理员。普通用户可以从自己的账户页经密码确认永久删除账号。云端删除不清除电脑本地的 Codex 原始会话，也不立即擦除运维备份；备份的保留和到期清理由运营方另行安排。

到期、停用或解绑只断开本产品的中继连接，不向用户电脑自动发送停止任务命令。本地已经提交的任务及队列可能继续执行，恢复连接后请核对实际状态。

## 隔离边界与额度

- 登录会话绑定服务端账号 ID；不信任请求体、查询或电脑快照中的 ownerId/deviceId。
- 每条设备、项目快照、会话缓存、命令和附件记录均按账号和电脑读取。不同账号可以有相同会话 ID，内容和回执仍独立。
- 设备凭据绑定唯一设备与账号；不能冒用另一台电脑身份或代答另一连接的请求。SSE 电脑目录与会话事件只发给所属账号。
- 一次性邀请与配对码只存摘要，用户密码使用加盐 scrypt；完整密码、邀请链接和设备令牌不会进入账号列表或审计记录。
- 管理页面不提供读取他人会话的入口。服务器运维人员仍控制数据库和存储，这不是端到端加密服务。
- 默认每账号最多 1 GiB 附件预留空间，整个实例默认最多 10 GiB；未发送附件默认 24 小时清理，已发送附件缓存默认 7 天。设备上限在兑换配对码时再次核对。

可在私有 `server.json` 配置：

```json
{
  "defaultDeviceLimit": 3,
  "attachmentQuotaBytes": 1073741824,
  "serverAttachmentQuotaBytes": 10737418240
}
```

这些字段合并进已有配置，不要覆盖账号、数据库路径或设备令牌。邀请页/创建页明确填写的电脑上限优先于默认值。实例总额度应配合磁盘、备份和实际容量设置，不代表已完成大规模容量测试。

## 反向代理与登录限流

默认只按 TCP 对端地址限流，不信任浏览器传入的 IP 头。Nginx 示例已覆盖 `X-Real-IP`；多用户上线时，应把实际反向代理的 TCP 地址加入私有配置的 `trustedProxies`，让限流按真实客户 IP 计数：

```json
{
  "trustedProxies": ["127.0.0.1", "::ffff:127.0.0.1"]
}
```

Docker 环境需要填写服务实际看到的代理地址，不是客户地址。代理必须覆盖客户端传入的 `X-Real-IP`，服务端口只允许受信任代理访问。不要为了方便而信任所有来源。其他代理可同样设置一个经过覆盖、验证的 `X-Real-IP`；未配置时同一代理后的客户共享登录限流。

## 验证与管理 API

执行 `npm test`、`npm run check`。浏览器验收需安装 Playwright 与 Edge，或通过 `PLAYWRIGHT_MODULE` 指定已有 Playwright 模块，再执行 `npm run test:browser:accounts`。

主要接口均使用本站登录 Cookie；写接口还要求 Origin 和 CSRF：

| 接口 | 用途 |
| --- | --- |
| `POST /api/register` | 兑换一次性邀请，不提供无邀请注册 |
| `GET /api/account` | 查看自己的账号与期限 |
| `POST /api/account/password` | 验证旧密码后修改，撤销所有网页登录 |
| `POST /api/account/delete` | 验证密码与账号后永久删除自己 |
| `GET /api/admin/accounts?q=&offset=` | 管理员分页搜索账号元数据 |
| `POST /api/admin/accounts` | 创建普通用户 |
| `POST /api/admin/accounts/:id` | 设置期限、续期、电脑上限或状态 |
| `POST /api/admin/accounts/:id/password` | 重置普通用户密码 |
| `POST /api/admin/accounts/:id/delete` | 删除普通用户 |
| `GET/POST /api/admin/invitations` | 查看邀请元数据或生成一次性邀请 |
| `POST /api/admin/invitations/:id/revoke` | 撤销邀请 |
