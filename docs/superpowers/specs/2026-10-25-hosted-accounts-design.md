# 托管版独立账号与权益管理

用户已授权补齐独立账号、数据隔离、设备归属、到期管理，并在验证后同步 GitHub。沿用已确认的同库双交付、邀请制托管方案，不再为每个客户部署独立实例。

## 实施范围

- 同一 SQLite 数据库内保存独立账号。旧配置账号首次迁移为管理员，保留密码、设备身份、历史、附件和有效登录；以后密码以数据库为准。
- 管理员创建用户或一次性邀请、设置服务天数和设备上限、续期、停用、重置密码、撤销邀请、删除用户；管理界面只提供账号与用量元数据，不提供他人对话入口。
- 用户使用邀请链接自主设置账号和密码。邀请链接只显示一次，数据库只存摘要；兑换时开始计算服务期。不开无邀请注册，不接入支付网关。
- 每次 HTTP 请求从登录会话获取账号归属；设备令牌解析为唯一账号与设备。API、WebSocket、SSE、命令回执、附件及配对均执行归属检查。
- 请求使用独立且不可变的账号 Store 视图，共享连接，不切换全局 ownerId。设备不能通过请求参数转移归属；必须解绑并以新账号重新配对。
- 到期账号仍可登录、查看自己的缓存、修改密码、解绑和删除数据；停止新配对、上传、新建和发送。电脑连接拒绝接入，已连接电脑在检查时断开；不向电脑发送停止已有本地任务的命令。续期后自动重连恢复。
- 停用账号撤销登录与未兑换配对码，立即断开网页事件流和电脑连接；恢复后可重新登录。删除账号清理会话缓存、命令、配对、设备凭据和附件，保留无凭据的删除标记，防止身份复用与旧配置复活。
- 附件额度按账号计算，并设置实例总额度；设备上限在兑换配对码时再次检查。管理员无限服务期，自托管用户可保持现有使用方式。
- 增加账户与套餐入口、邀请注册表单、管理员账号/邀请管理；保持现有手机会话界面和紧凑输入区。

## 验证

使用全新数据库和旧版本数据库分别验证。两个账号各绑定两台模拟电脑，复用相同会话、命令与项目 ID，验证各路由、事件流、下载、配对、伪造身份、续期、停用、删除、断线和重启。浏览器检查手机注册、管理账号、续期、过期提示和横向溢出。最后执行完整测试、语法检查、发布内容敏感信息审查和 GitHub CI。

发布源码不等于生产部署。生产升级必须使用一致性备份、匹配的回滚版本并验证迁移。
