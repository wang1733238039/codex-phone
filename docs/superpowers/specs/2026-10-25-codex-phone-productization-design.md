# Codex 随行产品化设计

日期：2026-10-25

状态：产品方向已确认，等待用户评审详细设计。

## 1. 背景与目标

Codex 随行目前是个人多电脑版本。手机网页连接到服务端，电脑连接程序通过出站 WebSocket 接入，并使用电脑本地 Codex 和项目。已有设备配对、项目分类、会话查看、续聊、新建对话和附件中继能力；尚未实现面向不同用户的账号隔离、注册和收费。

产品化采用两种交付方式：

1. 免费开源自托管版：用户从 GitHub 获取代码，在自己的服务器配置域名、HTTPS 和数据存储，并自行部署、升级和备份。
2. 付费托管版：用户注册并配对电脑后直接使用产品方提供的托管域名，由产品方负责服务器、更新、备份和运行维护。计划首发价为每账号每月人民币 9.9 元，正式开放前根据试用成本与服务容量复核额度和价格。

两种方式使用同一代码库和相同核心能力。付费版出售托管便利，不通过隐藏核心功能制造差异。模型调用继续走用户电脑上的 Codex 与用户已有渠道；平台不代理模型 API，也不收集上游模型密钥。

## 2. 用户与使用流程

### 自托管用户

1. 从 GitHub 获取发布版本。
2. 按 README 准备 Linux 服务器、域名和 HTTPS。
3. 使用 Docker Compose 初始化服务和首个管理员账号。
4. 在电脑安装连接程序，通过短时一次性配对码绑定设备。
5. 手机访问用户自己的域名，查看电脑列表并打开或创建会话。
6. 用户自行维护升级、备份、恢复和服务器安全。

### 托管版用户

1. 在托管网站注册或使用邀请制试用账号。
2. 在电脑安装连接程序，使用托管网站生成的一次性配对码完成绑定。
3. 手机登录后切换电脑，查看会话、创建对话、发送消息和材料。
4. 在账号设置中管理电脑、套餐、数据导出和账号删除。

电脑连接程序主动建立加密连接。电脑保持开机、联网且连接程序运行时，手机才能向它发送新任务；电脑离线时只能查看服务器已有缓存。

## 3. 产品边界

### 免费开源自托管版

- 提供完整的核心会话体验，不按功能人为削弱。
- 用户自行提供服务器、域名、证书和备份空间。
- README 说明环境要求、安装、升级、备份恢复、日志位置、卸载和数据清除。
- 用户承担服务器上的数据保护和可用性维护。
- 默认按个人单实例使用；不承诺官方托管、响应时限或持续运维支持。

### 付费托管版

- 首期邀请制，完成租户隔离和删除流程验证后再开放注册。
- 计划价格为每账号每月人民币 9.9 元；模型费用不包含在订阅中。
- 核心能力与自托管版一致，由服务方提供 HTTPS、服务器更新、备份、监控和基础使用支持。
- 正式收费前公布设备数、附件和历史缓存额度；额度根据容量与单用户成本测试设定，不承诺无限资源。
- 先以月付验证留存和成本，不预售长期套餐。

## 4. 架构与数据边界

### 共用代码与部署模式

- 维护一个主代码库、一套核心数据模型和一套连接协议。
- 自托管与托管环境通过部署配置区分；托管专属功能限于账号注册/邀请、套餐权益、计费状态、运营管理和服务监控。
- 首期沿用 Node.js、SQLite 和 Docker Compose 的单实例架构，先验证真实使用和容量，不引入微服务或 Kubernetes。
- 自托管实例使用用户自己的数据库与存储；托管实例为每个账号分配严格隔离的数据范围。

### 托管版租户隔离

- 每条用户、设备、会话、缓存、任务、审批和附件记录都必须有服务端确认的账号归属。
- API、事件流、WebSocket 路由、下载和附件续传均由登录身份推导账号范围，不信任客户端传入的 ownerId。
- 设备配对码短时有效、只能使用一次；配对后使用独立设备令牌，用户可撤销设备并使令牌立即失效。
- 不同账号之间的列表、历史、发送、任务状态、附件和实时事件必须完全隔离。
- 公开注册前完成跨账号越权测试、旧个人账号迁移和恢复演练。

### 会话内容与附件

- 托管版服务器会处理中继所需的用户消息和 Codex 回复，并缓存会话内容；附件会经过服务器转发。因此服务端不是“只存元数据”，产品隐私说明必须明确这一点。
- Codex、中转站和模型 API 密钥保留在用户电脑；服务端不读取或代理这些密钥。
- 不记录完整对话正文、上传文件内容、密码或设备令牌到运行日志。
- 继续采用临时附件中继策略：未发送的附件 24 小时清理，已发送附件缓存 7 天；电脑原文件不因服务器清理而删除。
- 会话缓存提供用户主动删除和账号删除能力。正式托管前公布缓存、备份和删除的实际保留期限，并实现对应的自动清理。
- 使用 TLS/WSS 保护传输；服务端可读取正在中继的明文内容，不宣称端到端加密。

## 5. 开源与版本发布

- 对外发布前补齐 LICENSE、NOTICE、依赖许可证清单和贡献说明。
- 推荐评估 AGPL-3.0 作为服务端与客户端的统一许可证，使提供网络服务的修改版按许可证履行源码提供义务；发布前核对现有依赖兼容性。
- 若最终选择允许任何人不公开修改就经营托管服务的宽松许可证，应接受第三方可基于项目提供商业托管服务。
- 发布包只包含源码、配置样例和部署文件；不包含个人账号、会话、日志、设备令牌、`.data` 或服务器生产配置。
- `.env`、账号密码、云端密钥与用户数据始终留在部署环境，不进入 Git 和容器镜像。

## 6. 分阶段交付

### 阶段 A：开源发行基础

- 整理项目发布结构、许可证和依赖清单。
- 完善一键部署配置、首次初始化、健康检查、日志脱敏、升级与备份恢复文档。
- 在干净 Linux 环境完成从零安装、升级、备份恢复和卸载验证。

验收：新用户仅按 README 能在自己的服务器完成部署；发布产物和 Git 历史不包含任何个人数据或密钥。

### 阶段 B：托管版多用户安全

- 增加独立账号、邀请制注册、登录退出和账号生命周期。
- 将所有服务端数据与路由改为账号范围隔离。
- 增加设备管理、令牌撤销、缓存删除和账号删除。
- 增加管理员运营入口，但管理员不默认拥有读取用户对话内容的功能。
- 建立跨账号数据隔离、配对、断线重连、附件和事件流测试。

验收：至少两个测试账号各绑定多台电脑；任何一个账号不能读取或操作另一个账号的数据；解绑后原设备凭据立即失效。

### 阶段 C：邀请制托管试用

- 在与个人自用数据隔离的托管环境部署。
- 对邀请用户开放账号和电脑配对。
- 按人民币 9.9 元/月验证付费意愿；先记录服务器、带宽、存储、备份和支持成本。
- 明确每账号设备数、缓存和附件额度；提供故障反馈、服务状态和数据删除入口。

验收：用户无需人工修改服务器文件即可注册/登录、配对、续聊、上传材料、查看任务状态和撤销电脑；用量达到限制时给出明确提示，不丢失用户数据。

### 阶段 D：公开发行与持续运营

- 自托管版本公开发布并维护版本说明与安全更新流程。
- 达到隔离、安全、容量和支持要求后开放托管注册及自动续费。
- 根据实际成本、使用频率和用户反馈调整 9.9 元价格及套餐额度。
- 再评估团队账号、更多操作系统和更长期的托管计划。

## 7. 非目标

- 不在云端运行 Codex，不托管用户项目文件或模型密钥。
- 不将其改造成通用远程桌面、远程 Shell 或任意电脑控制平台。
- 首发不做团队共享会话、协作编辑、跨电脑迁移运行中任务或企业级 SSO。
- 不在未经真实使用验证前承诺无限设备、无限附件、无限历史或服务可用性 SLA。

## 8. 主要风险与上线门槛

- 托管服务能接触用户会话内容与附件，必须先完成隔离测试、数据删除、备份策略和清晰的隐私说明。
- 9.9 元只是计划中的首发月价；只有测量可变成本并设定明确额度后才能公开销售。
- 当前项目目录位于尚无提交历史的 Git 工作区，项目文件显示为未跟踪。开始实施前应建立清晰的项目版本控制基线，避免把其他工作区文件混入产品提交。
- 目前 Windows 连接程序已有实际验证，macOS 分支尚未实机验证；首发支持范围应明确列出已测平台。
- 每次服务端升级需保留 SQLite 一致性备份和可恢复版本，托管多用户上线前必须演练恢复流程。

## 9. 评审结论

本设计采用“免费开源自托管 + 人民币 9.9 元/月托管版”的双交付模式，共用一套核心代码。先完善自托管发布能力，再完成托管版多用户隔离，之后邀请试用并以真实成本验证额度与价格。

需在实现计划前确认的产品决策：

1. 是否接受推荐的 AGPL-3.0 许可证方向。
2. 9.9 元作为试用期月价，正式额度在成本测试后确定。
3. 托管版先邀请码试用，安全与容量验收通过后再开放注册。
