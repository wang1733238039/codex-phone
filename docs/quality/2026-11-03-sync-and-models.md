# 消息与模型读取修复

## 结论与范围

4090 已更新本机连接程序，网页修复已部署到公网；实际手机尺寸浏览器验证可以展示最新 15 条消息、选择 11 个可用模型及其思考强度。7Q 在线但模型接口仍超时，尚未更新其本地连接程序；没有向 7Q 的 Codex 发送任何消息或任务。跨机部署结果不能由 4090 的结果替代。

前端最终 SHA256：`df20cc4aace34b14ab167cdb8c1d05b15ede4fc5d963ef4fcea5c22f6985b43a`。

## 故障证据

- 修复前两台电脑的 `/models` 均在约 25 秒后返回 504；手机 `model-select` 禁用，列表为空。
- 4090 会话详情能读取文本，但运行状态显示“读取电脑运行状态超时”。
- 运行中的连接程序已存活跨过桌面更新；Windows Codex 的几个旧版本目录已无 `codex.exe`，当前版本文件存在。独立启动当前 CLI 后初始化及模型查询约 220 毫秒完成。
- 代码回归证明：启动失败可能只有 `error/close`、没有 `exit`。旧客户端保留失效进程，稍后 `close()` 等待一个已经发过的事件，令后续 `start()` 永久等待。
- 更新连接程序后，4090 公网模型接口恢复 200，页面获得 11 个模型；新连接能识别当前桌面任务。

## 改动

- `src/codex.mjs`：查找 Windows 当前版本二进制，保留显式自定义路径；启动失败清理进程引用，隔离旧进程事件；初始化等待有界。
- `src/agent.mjs`：详情运行状态最多等待约 1.2 秒，同会话慢状态查询合并，缓存近期结果，较晚完成时通知页面补读。
- `public/app.js`：模型加载合并、失败退避及手动重试；设置入口明确显示“模型 / 设置”；网络及 SSE 恢复时补读；更新通知使用定时刷新而非持续重置计时；初始登录检查不能覆盖更晚的登录操作。
- 保留本机尚未发布的子对话工作，线上候选基于原生产脚本仅合入本次修改。
