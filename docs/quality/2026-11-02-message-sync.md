# 手机消息同步修复与线上验证

日期：2026-11-02。

## 定位与修复

4090 与 7Q 的连接均在线。4090 当前会话的公网强制读取与电脑本地消息一致；故障排查时最近窗口 15 条、会话共 157 条。

发现前端 `loadDetail(true)` 绕过忙碌标记，每次增加 `detailSeq`。当详情响应慢于持续的刷新请求时，所有返回都可能因序号过期而丢弃，页面一直显示旧记录或读取中。隔离浏览器使用 2 秒读取延迟和每 900 毫秒一次更新事件，旧实现超时失败。

新实现合并当前导航代次、电脑和会话的在途读取；重复强制刷新仅标记一次后续补读。先显示已有返回，再补读新状态；切换目标仍隔离旧响应。

## 验证

- 本地 390×844 手机浏览器：持续更新期间显示结果、单个在途读取、草稿保留、会话切换隔离、断网保留记录、恢复补读通过。
- 读取恢复没有向模型提交任务。
- `npm run check` 通过；`npm test` 的 81 项通过。
- 从生产版本提取仅本次读取修复，再运行相同浏览器回归通过。
- 公网真实登录，详情响应额外延迟 1.8 秒，同时每 900 毫秒刷新：正常显示 15 条消息，其中 7 条助手最终回复，与再次强制读取的消息内容一致。无页面脚本错误、无模型提交、无手机横向溢出。
- 已使用私有手机截图人工核对角色区分、消息可读性及输入区域。

测试工具：`tools/browser-sync-check.mjs`。可选 `SYNC_APP_FILE` 对指定前端脚本运行同一回归；`PLAYWRIGHT_MODULE` 指定已有 Playwright 模块。测试使用临时数据库与模拟连接，不触碰生产模型任务。
