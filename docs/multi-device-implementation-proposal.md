# 多电脑切换实现方案

日期：2026-10-23。状态：个人账号多电脑功能已实施。下文保留设计依据，并按实际交付更新。

交付：设备切换与管理、五分钟单次配对、独立电脑连接包、设备范围 API、缓存与浏览器状态隔离。25 项自动化测试及浏览器切换验证通过；一台实体原电脑已完成真实续聊，第二个模拟设备已完成公网配对与隔离验收。第二台实体电脑由用户转交 `CONNECT-ANOTHER-COMPUTER.md` 后接入；Windows 已实测，macOS 未实机验证。公开多用户与收费不在本轮范围。

## 1. 范围与选型

第一阶段仅实现现有个人账号管理多台电脑；不加入公开注册、收费、团队协作或跨电脑会话迁移。数据结构预留账号归属，避免后续产品化重新分割数据。

| 方式 | 改动与限制 | 结论 |
|---|---|---|
| 现有网站统一管理多台连接程序 | 改造连接、缓存与页面状态，保留一个域名和一次登录 | 推荐 |
| 每台电脑单独部署实例，再用网页列出入口 | 初步简单，但登录、缓存和维护分散；以后仍需合并 | 不作为主线 |
| 改接另一套原生手机 App / Host 产品 | 要同时调整手机端、主机接入与网络方案 | 不属于本次网页需求 |

继续使用现有 Node.js、SQLite、WebSocket 和原生网页。每台电脑主动连接现有服务器，手机与电脑无需处于同一 Wi-Fi。第二台电脑不必部署网站、开放公网端口或上传 Codex 密钥。

## 2. 使用流程

1. 手机登录现有网站，从顶部电脑菜单进入“添加电脑”。
2. 网站生成五分钟有效、单次使用的配对码。
3. 在第二台电脑运行连接程序的配对向导，填入网站地址、配对码和电脑名称。
4. 服务器建立设备记录，连接程序保存这台电脑自己的身份与凭据，并开始同步本机列表。
5. 手机选择“办公室”“家里电脑”或“笔记本”，显示该电脑自己的项目、置顶、归档和会话。

电脑菜单显示每台设备的在线状态、最后同步时间和手机任务数量。对话页持续显示电脑名称，避免仅在列表页知道执行目标。

切换电脑不停止另一台电脑正在运行的任务。电脑离线时保留缓存查看，禁用发送、停止和审批，不排队等待电脑上线执行。

“切换电脑”指选择执行目标，不代表把电脑 A 的会话、项目文件和运行中的任务转移到电脑 B。

## 3. 原单电脑问题与已完成改动

| 文件 | 改造前行为 | 已完成改动 |
|---|---|---|
| `src/server.mjs` | 全局单个 `agent`，第二个连接返回 409；运行状态、请求等待表与事件广播没有设备范围 | 使用设备连接表，所有请求和事件按设备路由 |
| `src/store.mjs` | 同步时全局删除 `threads`；历史和指令只用会话或请求 ID 查找 | 增加账号、设备归属，所有查询和写入要求显式范围 |
| `src/agent.mjs` | 使用共享令牌连接；异步响应通过当前 `this.ws` 发送 | 使用独立设备凭据，响应固定到接收请求时的连接 |
| `public/app.js` | 草稿、发送状态、折叠状态和 URL 只识别会话 ID | 增加设备选择，状态与地址按设备隔离，丢弃旧设备迟到响应 |
| `public/index.html`、`public/styles.css` | 仅显示当前电脑名称 | 增加紧凑设备菜单和添加、命名、解绑入口 |
| `tools/connect.mjs`、启动脚本 | 只更改服务器地址；首次配置生成一对共享令牌 | 新增配对流程，保留独立设备身份，适配现有后台启动与自启 |
| `test/`、`tools/browser-check.mjs` | 当前为单电脑用例 | 增加双连接、同 ID、离线、重连、切换和迁移验收 |

## 4. 设备身份与数据结构

设备身份使用随机 UUID，电脑名称只作为可编辑的显示信息。每台电脑获得独立随机凭据；服务器只保存摘要，通过认证确定账号和设备，不能相信消息正文自行声明的设备 ID。

配对码使用密码学随机数生成，建议 12 位易读 Base32 字符；服务端保存摘要，设置五分钟有效期、单次消费和失败限流。生成配对码要求已经登录并通过 CSRF 检查；成功领取时在事务中消费配对码并创建设备。设备凭据只在成功配对时返回，保存在本机私密配置，不作为命令行参数或写入日志。

已实现的数据表结构：

| 表 | 归属及主键 |
|---|---|
| `devices` | 随机 `id`、`owner_id`、名称、凭据摘要、创建时间、撤销状态；不持久化虚假的在线状态 |
| `pairings` | 配对码摘要、账号归属、失效时间、消费状态 |
| `threads` | 复合主键 `(owner_id, device_id, id)` |
| `details` | 复合主键 `(owner_id, device_id, id)`，保留正文版本和同步时间 |
| `commands` | 复合主键 `(owner_id, device_id, id)`，另存会话、提交状态和结果 |
| `device_meta` | 复合主键 `(owner_id, device_id, key)`，保存项目分类与最近同步时间 |

第一阶段账号归属由服务器现有个人配置确定，不开放新用户注册；以后多账号时由登录会话确定归属。

`snapshot(scope, threads, sidebar)` 只能替换目标设备的列表和分类。详情、审批、任务状态、幂等记录都使用同样的范围，避免从其他入口绕过设备隔离。

## 5. 服务端路由与连接规则

已实现接口：

```text
GET  /api/devices
GET  /api/devices/events
POST /api/device-pairings
POST /api/device-pairings/claim
POST /api/devices/:deviceId/rename
POST /api/devices/:deviceId/revoke

GET  /api/devices/:deviceId/status
GET  /api/devices/:deviceId/events
GET  /api/devices/:deviceId/threads
GET  /api/devices/:deviceId/threads/:threadId
POST /api/devices/:deviceId/threads/:threadId/send
POST /api/devices/:deviceId/threads/:threadId/stop
POST /api/devices/:deviceId/approve
GET  /api/devices/:deviceId/commands/:requestId
```

- 用 `Map<deviceId, connection>` 管理连接；连接记录包含账号、当前 socket、连接代次、心跳、手机任务与审批。
- 不同设备可同时在线。同一设备已有健康连接时拒绝第二个连接；旧连接超时后终止并允许重连，避免复制配置后两台电脑争用一个身份。
- 等待响应的请求绑定账号、设备、具体连接与连接代次；其他电脑即使知道请求 ID，也不能响应该请求。
- 某设备掉线只使该设备的等待请求结束并标记结果不确定，不影响其他设备。
- 电脑连接程序对异步请求的回复固定使用原接收连接；断线后的迟到结果不得发送到新连接以冒充当前响应。
- SSE 分为设备目录变化和所选设备状态两类：目录仅发布设备状态摘要，聊天、审批与会话变化仅发给对应设备的订阅者。
- 停止请求绑定明确的 threadId 和 turnId，审批绑定该设备当前连接中的请求与会话；连接程序再次校验，防止旧按钮停止新一轮任务或批准复用编号。
- 解绑立即撤销手机访问并断开连接，但不宣称已停止本机开始执行的任务；缓存删除作为单独明确操作。

旧的无设备 API 如需保留，只能固定映射到迁移时的原电脑，不能根据“最近在线”或全局选择自动改路由。

## 6. 手机切换与竞态处理

手机持有明确的 `deviceId`。进入页面先加载设备列表，再加载选定电脑的列表；无设备时显示添加入口，离线设备不会被自动替换为在线设备。

切换流程：

1. 按原电脑与会话保存草稿、滚动位置和发送结果待确认状态。
2. 更新选择代次，取消旧读取、关闭旧设备 SSE，清空旧列表、详情与审批展示。
3. 设置目标电脑，加载其状态和会话列表，建立目标设备 SSE。
4. 只有设备、会话和选择代次都匹配，响应才能更新当前界面。

所有浏览器状态采用账号、设备、会话或项目的组合键，包括草稿、折叠、最近访问及待确认发送。两台电脑即使存在相同 threadId，也完全独立。

新地址同时包含设备和会话，例如 `#/devices/<deviceId>/threads/<threadId>`。旧版 `#<threadId>` 只解析到迁移时的原电脑，不能落到上一次选中的其他电脑。

发送时捕获固定的设备、会话和 requestId。用户切到另一台电脑后，原请求完成仅更新原目标的状态，不清空新电脑的输入框，不弹出让人误认目标的结果。原设备任务继续执行，用户切回可查看结果。

## 7. 旧数据迁移与上线顺序

1. 在无本产品手机任务运行时备份配置与 SQLite 一致性快照；不能只复制 WAL 模式下的主数据库文件。
2. 建立持久的原电脑设备记录，事务迁移现有会话、分类、详情及指令，校验数量、归属及历史版本。未确认的旧指令保持 unknown，不自动执行。
3. 现有连接令牌可以暂时只绑定原电脑，以兼容升级期间旧连接；它不再具有注册或连接其他电脑的权限。后续换成专属凭据后撤销旧值。
4. 更新服务器并核验原电脑连接、登录、列表、历史和控制，再更新手机页面和第二台电脑配对工具。
5. 本地服务与公网属于不同服务器实例，分别保存设备注册，不从配置信息推断“它们必然已互相绑定”。
6. 保留上线前镜像、配置和数据库快照；回退必须同时处理对应数据库版本，不能只回退程序后让旧版读取新版结构。

此改造不写入原生 Codex 数据库，不迁移模型配置，不修改中转站，不强制结束桌面任务或抢占会话锁。

## 8. 验收与实施拆分

| 批次 | 交付 | 必验内容 |
|---|---|---|
| A：设备存储与协议 | 注册表、配对、迁移、设备范围 API 与连接路由 | 两个模拟连接同时在线；同 threadId 仍独立；A 同步不删除 B；A 掉线不影响 B；错误设备无法响应请求 |
| B：手机与连接工具 | 设备菜单、配对工具、独立浏览器状态、设备事件 | A 请求晚于切换到 B 才返回不串内容；发送结果不清空 B 草稿；停止与审批固定正确目标；旧链接仍进入原电脑 |
| C：部署与实体接入 | 原电脑无损升级、第二台电脑配对、手机访问 | 两台实体电脑同时在线并切换；各自读取和独立测试会话续聊；解绑生效；断线重连；缓存正确 |

自动化先用两个模拟连接验证隔离，不向用户既有会话发送测试消息。实体续聊使用专用测试会话。第二台电脑尚未接入前，不能将模拟连接通过表述为“双实体电脑已验证”。

A、B 已完成；C 已完成原电脑升级、服务器部署、公网配对与模拟设备验收。自托管实例应自行保留升级前备份，回退说明见 `deployment.md`。
